# כלי העברת הנתונים של לארג' פעמי (ריבוי עסקים, שלב 4)

הכלי מעתיק את הנתונים של לארג' פעמי מהשורש (`admins`, `staff`, `cfg`, `inbox` וכו') אל העסק הראשון במבנה החדש: `b/largpeami/...`.
**המקור לא נמחק ולא משתנה.** הוא נשאר כגיבוי עד שהמשתמש יאשר אחרת.

> **אזהרה:** הכלי נבדק רק באמולטור, עם נתוני דמה. הרצה על פרויקט אמיתי (גם על `largpeami-test-f4691`) רק באישור מפורש של המשתמש, ורק דרך התהליך הידני ב-GitHub (`.github/workflows/migrate-largpeami.yml`).

## מה יש כאן
| קובץ | מה הוא עושה |
|---|---|
| `migrate.js` | הכלי. פקודות: `backup`, `dry-run`, `copy`, `verify`, `compare-backup`, `report-since`, `set-dataroot` |
| `fsrest.js` | גישה ל-Firestore דרך REST, עם ההגנות על הכתיבה (ראו למטה) |
| `guard.js` | בדיקת השומר לפני הרצה על פרויקט אמיתי |
| `ROLLBACK.md` | מסמך חזרה, צעד אחר צעד |
| `../tests/migrate-tool.test.js` | הבדיקות באמולטור |

## שלבי העבודה
1. **גיבוי** (`backup --out backup.json`): כל האוספים בשורש (חוץ מ-`b`), כולל תת-אוספים, לקובץ JSON. לכל מסמך נשמרים הערכים הגולמיים של Firestore, גיבוב (SHA-256), ותווית זמן. אחרי הכתיבה הכלי קורא את הקובץ שוב ומוודא שכל גיבוב יוצא זהה.
2. **ספירה** (`dry-run`): מציג כמה מסמכים ייווצרו, יתעדכנו או יתנגשו. לא כותב כלום, גם לא ליעד.
3. **העתקה** (`copy --mode write --state state.json --backup backup.json`): יוצר את המסמכים ב-`b/<bizId>/...`, מעתיק את קבצי `app_backups/` ב-Storage אל `b/<bizId>/app_backups/`, יוצר `users/{uid}` לכל מנהל ועובד, ויוצר את מסמך העסק `b/<bizId>` (`status: active`, `dataRoot: legacy`, כל התוספות מופעלות). מסמך עסק קיים לא נדרס.
4. **אימות** (`verify`): ספירה וגיבוב לכל אוסף, מקור מול יעד, ודוח הבדלים. גם מספר קבצי Storage וגודלם.
5. **השלמה**: מריצים שוב את `copy` עם אותו `--state`. רק מה שהשתנה במקור מאז ההעתקה הקודמת מועתק. מסמך ששונה גם ביעד מדווח "התנגשות", עם שני הגיבובים, ולא נכתב. הרצה בלי שינוי במקור לא כותבת דבר.
6. **חזרה**: ראו `ROLLBACK.md` (`set-dataroot --to legacy`, ו-`report-since` שמראה מה נכתב ב-`b/` מאז ההעתקה).

## אילו אוספים
- **מועתקים:** `admins`, `staff`, `cfg`, `bk`, `chunks`, `inbox`, `app_backup_status`, `shelf`, `fb`, `tasks` (+`c`), `supinv` (+`p`), `appreq` (+`p`), `closings` (+`p`), `cashout`, `deposits` (+`p`), `zlast`, `yemot_*`, `voice_usage`, `scan_usage`. כל תת-אוסף אחר שנמצא מתחת להם מועתק גם הוא.
- **מגובים ולא מועתקים (הזמנות אתר, נדחה לסבב נפרד):** `site_income_daily` ואוספי `orders/`.
- **אוסף שלא מופיע ברשימות:** מגובה, לא מועתק, ומסומן "לא ידוע" בפלט. ההחלטה מה לעשות בו – של המשתמש.

## ההגנות
- ברירת המחדל: קריאה בלבד. כתיבה רק עם `--mode write`.
- כתיבה רק ל-`b/<bizId>`, ל-`b/<bizId>/...`, וליצירה של `users/<uid>` חדש. כל ניסיון לכתוב למקום אחר נעצר בקוד.
- כל כתיבה עם תנאי מוקדם: יצירה רק אם המסמך לא קיים, ועדכון רק אם מסמך היעד לא השתנה מאז שנקרא.
- אין בקוד מחיקה (לא `DELETE` ולא `delete` בכתיבה המרוכזת). בקבצי Storage מועתק רק קובץ שלא קיים ביעד. בענן הבדיקה נעשית גם בתנאי `ifGenerationMatch: 0`. באמולטור התנאי הזה לא נאכף, ולכן הכלי בודק קודם שהקובץ לא קיים.
- נעילה: קובץ `<state>.lock` מונע שתי העתקות במקביל באותו מחשב. בתהליך ב-GitHub יש גם `concurrency`.
- בלי אמולטור, הכלי מסרב לרוץ אם בדיקת השומר (`guard.js`) לא עברה.
- טיפוסים נשמרים בדיוק: הנתונים עוברים בצורה הגולמית של Firestore. firebase-admin היה הופך סכום שלם שנשמר כ-`doubleValue` (כך האפליקציה שומרת סכומים) ל-`integerValue`. כאן זה לא קורה.

## הרצה באמולטור (פיתוח ובדיקות)
```bash
cd firebase
firebase emulators:exec --only firestore,storage --project demo-largpeami \
  "node --test tests/migrate-tool.test.js"
```
באמולטור מותר רק פרויקט `demo-*`.

## הרצה על פרויקט אמיתי – רק באישור המשתמש, דרך GitHub
Actions ← "Migrate largpeami data" ← Run workflow:
- `project_id` ו-`project_id_confirm`: מזהה הפרויקט המלא, פעמיים.
- `mode`: `readonly` (ברירת מחדל: גיבוי, ספירה ואימות) או `write`. ב-`write` צריך להקליד גם `write_confirm` = `write-to-<מזהה>`.
- מזהה שמכיל `test` דורש גם `allow_test_project` = `true`.
- להשלמה: `state_run_id` = מספר ההרצה הקודמת (משם נלקח קובץ המצב).
- `upload_backup`: האם להעלות את קובץ הגיבוי (שמכיל את כל הנתונים) כ-artifact. ברירת המחדל: לא.

### ייצוא מנוהל של Firestore (גיבוי נוסף, לפני ההעתקה) – טקסט בלבד, לא מורץ על ידי הכלי
```bash
# דורש gcloud מחובר לחשבון עם הרשאה, ו-bucket ייעודי לגיבויים (לבחור לפני ההרצה)
gcloud firestore export gs://<BUCKET-לגיבויים>/firestore-export-$(date -u +%Y%m%d-%H%M%S) --project=<PROJECT_ID>
```
שחזור מייצוא כזה (`gcloud firestore import`) **דורס** מסמכים בפרויקט. משתמשים בו רק במקרה חירום, ורק באישור.
